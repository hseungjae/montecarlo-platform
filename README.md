# simcore

분산 몬테카를로 시뮬레이션 플랫폼의 계산 엔진입니다. 이 저장소는 로드맵의 **Phase 0**으로, 워커가 청크 하나를 계산하는 코드와 그 정확성 테스트, 처리 속도 측정 도구까지 담고 있습니다.

설계서: [docs/DESIGN.md](docs/DESIGN.md)

## 실행

```bash
uv sync                      # Python 3.12 가상환경 + NumPy, pytest
uv run pytest                # 테스트 36개
uv run python -m simcore run --seed 42 --gamblers 1000000 --chunk 250000
uv run python -m simcore bench --seed 1
```

`run`은 작업 하나를 로컬에서 끝까지 돌립니다. 순서(계획 → 청크 계산 → 합치기)는 Phase 1에서 API와 워커가 나눠 맡을 일과 같습니다. `bench`는 코어당 처리 속도를 재고, 25초짜리 청크와 "1코어 1시간" 기준 작업의 크기를 계산합니다.

## 구조

| 파일 | 역할 | Phase 1에서 쓰는 곳 |
| --- | --- | --- |
| `simcore/games.py` | 베팅 종류: 결과별 확률과 순배당(퍼센트 정수) | API 프리셋 |
| `simcore/strategies.py` | 고정 베팅, 마틴게일(테이블 한도, 목표 수익 중단) | 워커 |
| `simcore/seeding.py` | 시드 규칙: (작업 시드, 청크 번호) → 난수열 | 워커 |
| `simcore/engine.py` | `plan_job` 작업 계획, `run_chunk` 청크 계산 | `plan_job`은 API, `run_chunk`는 워커 |
| `simcore/histogram.py` | 계급 경계, 도수 세기, `Summary.merge` 청크 합치기 | API 결과 조회·SSE |
| `simcore/cli.py` | `run`, `bench` 명령 | 로컬 확인용 |

## Phase 0 통과 기준

| 기준 | 테스트 | 결과 |
| --- | --- | --- |
| 이론값과 일치 | `tests/test_theory.py`: 베팅 6종의 고정 베팅 평균이 이론 기댓값의 99% 신뢰구간 안. 마틴게일도 "기대 수익 = 하우스 엣지 × 총 베팅액"(Wald 등식)을 만족 | 통과 |
| 같은 시드 = 같은 결과 | `tests/test_reproducibility.py`: 같은 청크는 몇 번을 계산해도 같고, 청크끼리는 다른 난수열을 씀 | 통과 |
| 합치기가 정확 | `tests/test_merge.py`: 청크 결과를 어떤 순서로 합쳐도 같고, 원본 값으로 직접 만든 도수분포표와 같음. 같은 청크가 두 번 오면 거부 | 통과 |

금액은 모두 정수 센트(1칩 = 100센트)라서 합계와 제곱합이 합치는 순서와 상관없이 정확히 같습니다. 같은 시드로 같은 결과를 내려면 모든 워커가 같은 NumPy 버전을 써야 하므로, 버전은 `uv.lock`이 고정합니다(현재 2.5.5).

## 측정 결과

Apple M2 노트북, 1코어, 시작 자금 1,000칩, 최대 1,000판 기준입니다. 클라우드 인스턴스의 코어 속도는 다르므로 Phase 2에서 다시 잽니다.

| 설정 | 1인당 평균 판 수 | 처리 속도 | 25초 청크 크기 |
| --- | --- | --- | --- |
| 빨강 · 마틴게일, 한도 500칩 (기준 작업) | 813판 | 약 3,300만~3,700만 판/초 | 도박사 약 100만 명 |
| 빨강 · 고정 베팅 1칩 | 1,000판 | 약 4,300만 판/초 | 도박사 약 107만 명 |
| 숫자 하나 · 마틴게일, 한도 500칩 | 28판 | 기준 작업으로 부적합 | — |

- 도박사 100만 명짜리 청크 하나가 23초, 최대 메모리 190MB입니다. 워커 메모리 요청 512Mi로 충분합니다.
- 1코어 1시간 기준 작업은 빨강 마틴게일 1,000판 × 도박사 약 1억 4,500만 명입니다. 이를 3분 안에 끝내려면 약 20코어가 필요합니다.

## 설계서와 달라진 점

1. **시드 규칙**: 청크는 `spawn_key=(0, 청크 번호)`, 파일럿 실행은 `spawn_key=(1,)`을 씁니다. 두 난수열이 절대 겹치지 않게 앞자리로 구분했습니다.
2. **계급 경계**: 고정 베팅도 파산이나 목표 수익 중단이 있으면 이론식이 맞지 않아서, 모든 전략에 파일럿 실행(도박사 1만 명)을 씁니다.
3. **청크 결과 열 추가**: `losers`(돈 잃은 사람 수), `sum_wagered`(총 베팅액), `rounds_played`(실제 판 수). 손실 비율, 실제 손실률, 처리량 메트릭에 필요합니다.
4. **기준 작업**: "빨강" 마틴게일입니다. "숫자 하나" 마틴게일은 1인당 평균 28판 만에 파산해서 계산량이 너무 작습니다.
